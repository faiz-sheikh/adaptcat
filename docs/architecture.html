§ 03 The CAT Algorithm — Item Response Theory

3.1 Why IRT over Classical Test Theory (CTT)?

Classical Test Theory produces scores dependent on the specific question set used. If two students take different questions, their raw scores can't be fairly compared. IRT solves this by estimating an ability parameter θ that is question-independent — the same student would get the same θ regardless of which specific questions they answered, as long as the questions have calibrated IRT parameters.

❌ Classical Test Theory (CTT)
  • Score = number of correct answers
  • Difficulty = % of students who answered correctly (sample-dependent)
  • Comparing two tests is only valid if same questions used
  • Easy questions contribute same to score as hard ones
  • No probabilistic model of how a student of ability θ responds
✓ Item Response Theory (IRT)
  • Estimates θ — a continuous ability on a latent trait scale
  • Question parameters (b, a, c) are student-sample independent
  • Can compare students across different question sets
  • Hard questions answered correctly provide more information
  • Probabilistic model: P(correct | θ, b, a, c)

3.2 The 3-Parameter Logistic Model (3PL)

We use the 3PL model, which is the gold standard used by ETS (GRE, TOEFL) and College Board (SAT/AP):

3PL Item Characteristic Curve
P(X=1 | θ, a, b, c) = c + (1-c) × 1 / (1 + e^(-Da(θ-b)))
Where: θ = examinee ability (standard normal, typically −3 to +3) a = discrimination parameter (slope; higher = better separator of ability levels) b = difficulty parameter (θ at which P = 0.5+c/2; higher = harder) c = pseudo-guessing parameter (lower asymptote; typically 0.25 for 4-option MCQ) D = 1.702 (scaling constant to align logistic with normal-ogive)

3.4 Theta Estimation — Maximum Likelihood (MLE) + EAP

After each response, we update θ using two methods depending on response count:

Phase 1: Expected A Posteriori (EAP) — First 5 Q

With few observations, MLE is unstable (can be ±∞ for all-correct or all-wrong streaks). EAP uses a prior distribution and Bayes' theorem:

θ_EAP = Σ [θ_k × L(X|θ_k) × π(θ_k)] / Σ [L(X|θ_k) × π(θ_k)]
Prior π(θ) = Normal(0, 1). Quadrature points θ_k from −4 to +4.
Phase 2: Maximum Likelihood (MLE) — Q6 onwards

With sufficient data, MLE gives a sharper estimate. We maximise the log-likelihood via Newton-Raphson iteration:

θ_{t+1} = θ_t + L'(θ_t) / L''(θ_t)
L'= first derivative of log-likelihood. L''= second derivative (negative Fisher Information). Converges in 3-5 iterations.

3.5 Item Selection — Maximum Fisher Information

At each step, we select the question that maximises the Fisher Information at the current θ estimate — the question that will most reduce our uncertainty about the student's true ability:

Fisher Information Function for 3PL
I(θ) = a² × [(P(θ) - c)² × Q(θ)] / [(1-c)² × P(θ)]
Where P(θ) = 3PL probability, Q(θ) = 1 - P(θ). Maximum information occurs when P(θ) ≈ c + (1-c)/2 — i.e., question difficulty b ≈ current θ. This is why the algorithm converges: it keeps selecting questions near the student's estimated ability.

3.6 Stopping Rules

The test stops when any of these conditions is met:

  • Fixed length: Section question count exhausted (24 for English, etc.)
  • Precision threshold: Standard Error of θ falls below 0.30 (high confidence)
  • Time limit: Section timer expires
  • Content constraint: All subsections covered (minimum 1 question per concept tag)

// AdaptCAT v3 — SectionEngine core logic (JavaScript)
// Rule: Correct → diff+1 (max 5) | Wrong → reset to diff=1
// This is a "mastery model" — not full IRT but maps well to AMCAT's level system

class SectionEngine {
  onAnswer(q, isCorrect, timeSec) {
    // Mastery model: advance on correct, RESET on wrong
    if (isCorrect) {
      this.diff = Math.min(5, this.diff + 1);
    } else {
      this.diff = 1;  // FULL RESET — clean slate
    }
    // Wilson Score Bayesian difficulty update (persists across sessions)
    updateQStat(q.id, q.diff, isCorrect, timeSec);
  }
}

// Wilson Score lower bound — conservative pass-rate estimate
function updateQStat(id, diff, correct, timeSec) {
  const s = qStats[id];
  s.attempts++;
  if (correct) s.correct++;
  const n = s.attempts, p = s.correct / n;
  const z = 1.645;  // 90% confidence
  const wilson_lo = (p + z*z/(2*n) - z*Math.sqrt(p*(1-p)/n + z*z/(4*n*n))) / (1 + z*z/n);
  // Map wilson_lo → difficulty: high pass rate = easier question
  const implied_diff = Math.max(1, Math.min(5, 5 - (wilson_lo * 4)));
  const trust = Math.min(n / 15, 0.75);
  s.adjustedDiff = s.adjustedDiff * (1 - trust) + implied_diff * trust;
}

3.8 Production Upgrade Path — Full 3PL IRT (Python/FastAPI)

# Production IRT backend (Python — constraint compliant, no f-strings, no .values)
import numpy as np
from scipy.optimize import minimize_scalar
from typing import List, Tuple, Dict

D = 1.702  # IRT logistic scaling constant

def icc_3pl(theta: float, a: float, b: float, c: float) -> float:
    """3PL Item Characteristic Curve. Returns P(correct | theta, a, b, c)."""
    exponent = -D * a * (theta - b)
    return c + (1 - c) / (1 + np.exp(exponent))

def fisher_information(theta: float, a: float, b: float, c: float) -> float:
    """Fisher Information at theta for one item."""
    p = icc_3pl(theta, a, b, c)
    q = 1 - p
    numerator = (D * a) ** 2 * (p - c) ** 2 * q
    denominator = (1 - c) ** 2 * p
    return numerator / denominator if denominator > 0 else 0.0

def log_likelihood(theta: float, responses: List[Tuple]) -> float:
    """Log-likelihood of response pattern given theta."""
    ll = 0.0
    for (correct, a, b, c) in responses:
        p = icc_3pl(theta, a, b, c)
        p = np.clip(p, 1e-9, 1 - 1e-9)
        ll += correct * np.log(p) + (1 - correct) * np.log(1 - p)
    return ll

def estimate_theta_mle(responses: List[Tuple]) -> Tuple[float, float]:
    """MLE theta estimation. Returns (theta_hat, standard_error)."""
    result = minimize_scalar(
        lambda t: -log_likelihood(t, responses),
        bounds=(-4.0, 4.0),
        method='bounded'
    )
    theta_hat = np.clip(result.x, -3.5, 3.5)
    # Standard error = 1 / sqrt(sum of Fisher Information)
    total_info = sum(fisher_information(theta_hat, a, b, c) for (_, a, b, c) in responses)
    se = 1.0 / np.sqrt(total_info) if total_info > 0 else 1.5
    return float(theta_hat), float(se)

def select_next_item(theta: float, se: float, candidate_items: List[Dict]) -> Dict:
    """Select item maximising Fisher Information at current theta."""
    best_item = None
    best_info = -1.0
    for item in candidate_items:
        info = fisher_information(theta, item['a'], item['b'], item['c'])
        if info > best_info:
            best_info = info
            best_item = item
    return best_item

def should_stop(se: float, n_answered: int, max_items: int) -> bool:
    """Stopping rule: precision threshold or max items reached."""
    return se < 0.30 or n_answered >= max_items
§ 04 ML Learning Loops — Online & Offline Training

4.1 Two-Stage Learning Architecture

⚡ Online Learning (Real-time)

Happens after every individual answer. Runs in-browser (current) or via micro-API call (production).

  • Wilson Score update: Updates question's empirical pass rate with confidence weighting
  • Theta update: MLE/EAP updates student's current session θ after each answer
  • Mastery tracking: Streak, level, time-per-question tracked per concept tag
  • Flag accumulation: Users can flag confusing questions; accumulates for offline review
🔄 Offline Retraining (Periodic)

Batch process on entire response database. Runs bi-weekly in production.

  • Full IRT calibration: EM algorithm re-estimates a, b, c for all questions using all responses
  • Anomaly detection: Questions with unexpected response patterns (cheating signals) flagged
  • Concept drift detection: Topics where overall performance changes significantly
  • Bank quality audit: Questions with poor fit indices retired or sent for revision

4.2 The "High Performer Misses Medium Question" Scenario

When θ̂ = +1.8 (Advanced) but the student answers a b=0.0 (Medium) question incorrectly:

1
Immediate: Online Theta Update
MLE re-estimates θ downward. The unexpected wrong answer on an easy item provides strong information. θ might drop from +1.8 to +1.3. The next question selected will be slightly easier (b ≈ +1.3) to sharpen the estimate.
2
Immediate: Question Wilson Score Update
The question's correct_count stays same, attempts++ by 1. Pass rate drops slightly. If this pattern persists (many high-ability users missing this question), Wilson Score will shift, implied_diff increases, and adjustedDiff drifts toward Level 4 from its current Level 3 label.
3
Offline: IRT Recalibration
In bi-weekly retraining, the EM algorithm re-estimates b for this question from the response matrix. If consistently missed by high-θ students, b (difficulty) will be estimated higher. The question may also show a negative discrimination (a < 0) indicating something is wrong with it — it gets flagged for expert review.
4
Session Report: Concept Gap Identified
The student's report shows: "Missed a Level 3 question in Applied Math → concept: profit_loss_discount. Despite high overall score, this specific concept may need attention." Trainability note: "Question type was conceptual (Bloom: Apply). Student tends to struggle with application questions despite strong knowledge questions."

4.3 Offline Training — Python Pipeline (Constraint-Compliant)

# Offline IRT calibration — EM Algorithm
# Compliant: no f-strings, no .values, no informal structures
import numpy as np
from scipy.optimize import minimize
from typing import List, Dict, Any

def build_response_matrix(responses: List[Dict[str, Any]]) -> tuple:
    """Build item x person response matrix from response records.
    Returns: (matrix, theta_init, item_ids, person_ids)"""
    person_ids = list(set(r['person_id'] for r in responses))
    item_ids   = list(set(r['item_id']   for r in responses))
    p_idx = {pid: i for i, pid in enumerate(person_ids)}
    i_idx = {iid: i for i, iid in enumerate(item_ids)}
    matrix = np.full((len(person_ids), len(item_ids)), np.nan)
    for r in responses:
        row = p_idx[r['person_id']]
        col = i_idx[r['item_id']]
        matrix[row, col] = float(r['correct'])
    # Initialise theta from proportion correct per person
    person_means = np.nanmean(matrix, axis=1)
    theta_init = np.clip(2.0 * person_means - 1.0, -3.0, 3.0)
    return matrix, theta_init, item_ids, person_ids

def em_calibrate_items(matrix: np.ndarray, theta_init: np.ndarray,
                        n_iter: int = 20) -> np.ndarray:
    """EM calibration of b parameters (1PL Rasch model).
    Returns: array of b parameters, shape (n_items,)"""
    theta = theta_init.copy()
    n_persons, n_items = matrix.shape
    b_params = np.zeros(n_items)

    for iteration in range(n_iter):
        # E-step: update theta given current b
        for j in range(n_persons):
            observed = matrix[j, :]
            mask = ~np.isnan(observed)
            if np.sum(mask) == 0:
                continue
            obs_b = b_params[mask]
            obs_r = observed[mask]
            def neg_ll_person(t):
                p = 1.0 / (1.0 + np.exp(-(t - obs_b)))
                p = np.clip(p, 1e-9, 1 - 1e-9)
                return -np.sum(obs_r * np.log(p) + (1 - obs_r) * np.log(1 - p))
            result = minimize(neg_ll_person, theta[j], method='L-BFGS-B',
                              bounds=[(-4.0, 4.0)])
            theta[j] = result.x[0]

        # M-step: update b given current theta
        for i in range(n_items):
            observed = matrix[:, i]
            mask = ~np.isnan(observed)
            if np.sum(mask) < 5:
                continue
            obs_theta = theta[mask]
            obs_r = observed[mask]
            def neg_ll_item(b):
                p = 1.0 / (1.0 + np.exp(-(obs_theta - b)))
                p = np.clip(p, 1e-9, 1 - 1e-9)
                return -np.sum(obs_r * np.log(p) + (1 - obs_r) * np.log(1 - p))
            result = minimize(neg_ll_item, b_params[i], method='L-BFGS-B',
                              bounds=[(-3.5, 3.5)])
            b_params[i] = result.x[0]

    return b_params

// components/TestEngine.tsx
import React, { useState, useCallback, useEffect } from 'react';
import { selectNextItem, updateTheta, shouldStop } from '../lib/irt';

interface TestEngineProps {
  sectionConfig: SectionConfig;
  questionPool: Question[];
  onSectionComplete: (result: SectionResult) => void;
}

const TestEngine: React.FC<TestEngineProps> = ({
  sectionConfig,
  questionPool,
  onSectionComplete
}) => {
  const [session, setSession] = useState<SessionState>({
    theta: 0,
    standardError: 1.5,
    responses: [],
    currentSection: sectionConfig.id,
    difficultyLevel: 1
  });
  const [currentQ, setCurrentQ] = useState<Question | null>(() =>
    selectNextItem(session.theta, session.standardError, questionPool, new Set())
  );

  const handleAnswer = useCallback((selectedIndex: number) => {
    if (!currentQ) return;
    const isCorrect = selectedIndex === currentQ.correctIndex;
    const newResponse = { itemId: currentQ.id, correct: isCorrect,
                         a: currentQ.aParam, b: currentQ.bParam, c: currentQ.cParam };
    const newResponses = [...session.responses, newResponse];
    const [newTheta, newSE] = updateTheta(newResponses);
    const answered = new Set(newResponses.map(r => r.itemId));

    setSession(prev => ({
      ...prev,
      theta: newTheta,
      standardError: newSE,
      responses: newResponses,
      difficultyLevel: isCorrect ? Math.min(5, prev.difficultyLevel + 1) : 1
    }));

    if (shouldStop(newSE, newResponses.length, sectionConfig.maxQuestions)) {
      onSectionComplete({ theta: newTheta, se: newSE, responses: newResponses });
    } else {
      setCurrentQ(selectNextItem(newTheta, newSE, questionPool, answered));
    }
  }, [currentQ, session, questionPool, sectionConfig, onSectionComplete]);

  return (
    <div className="test-engine">
      <SectionHeader section={sectionConfig} theta={session.theta} />
      <AbilityGauge theta={session.theta} se={session.standardError} />
      {currentQ && <QuestionCard question={currentQ} onAnswer={handleAnswer} />}
    </div>
  );
};

6.4 Security Considerations

  • Anti-cheating: Question IDs never exposed to client. Only stems sent. Answer verified server-side.
  • Rate limiting: Max 1 answer per 5 seconds per session. Prevents scripted submission.
  • Session isolation: Each test session is a signed JWT. Cannot resume another user's session.
  • Code execution sandbox: Judge0 runs in isolated containers. No filesystem access. 5-second timeout.
  • API key protection: Anthropic key never leaves backend. Frontend only communicates with your FastAPI.
